# AGENTS.md

## Project Goal

This repository implements Web-VLMAgent, a course project for "Principles and Applications of Multimodal Large Models".

The goal is to build a reproducible multimodal web agent that can complete web tasks from natural language instructions by observing webpage screenshots, DOM information, accessibility tree information, and Set-of-Marks annotated screenshots.

The system should support browser automation, structured actions, trace logging, batch evaluation, error analysis, and report-ready results.

## Course Requirements

The course topic is "Web Multimodal Agent: interface understanding + automatic operation".

Minimum requirements:
- Select 1-2 real websites.
- Design at least 3 task scenarios for each website.
- Run at least 10 independent tests for each scenario, at least 60 tests in total.
- Report task success rate.
- Classify failure types: perception failure, planning failure, execution failure, verification failure, website/environment failure.
- Provide visual operation trajectories, including screenshot sequences and action sequences.
- Submit code repository, final report, and demo video.

Our goal is to exceed the minimum requirements by implementing:
- easy / medium / hard task levels;
- Set-of-Marks grounding;
- screenshot + DOM + accessibility-tree hybrid observation;
- ReAct-style planning;
- Progress Checker;
- Final Verifier;
- batch evaluation;
- trace replay;
- ablation experiments.

## Architecture

The main loop is:

Observe -> Plan -> Act -> Check -> Verify

Observation includes:
- raw screenshot;
- DOM candidate elements;
- accessibility tree when available;
- Set-of-Marks annotated screenshot (sent as image_url to vision-capable models).

When using `--provider gemini` or `--provider openai`, the SoM marked screenshot
is encoded as base64 and sent alongside the text prompt for visual grounding.
When using `--provider deepseek`, only text observations are sent.

The agent must output structured JSON actions only.

Supported actions:
- click
- type
- scroll
- press
- back
- wait
- answer
- done
- ask_user
- navigate
- search

## Safety Constraints

The agent must not perform:
- login with real credentials;
- payment;
- purchase;
- deletion;
- irreversible submission;
- sending private information;
- bypassing CAPTCHA;
- scraping at abusive scale.

Tasks should use public webpages, documentation pages, GitHub pages, arXiv pages, Hugging Face model cards, or local sandbox pages.

## Coding Rules

- Keep modules small and readable.
- Add type hints where practical.
- Use Pydantic or dataclasses for structured actions and task schemas.
- Validate every model output before executing it.
- Never execute arbitrary code generated by a model.
- Save all important artifacts for each step:
  - screenshot.png
  - marked_screenshot.png
  - candidates.json
  - prompt.txt
  - raw_response.txt
  - parsed_action.json
  - execution_result.json
- Prefer deterministic, debuggable code over clever abstractions.
- Handle CJK encoding gracefully: some API proxies corrupt Chinese text;
  the FinalVerifier includes an ASCII/numeric fallback to verify answers
  when character-level matching fails.

## Trace Format

Each run should be saved under:

traces/{task_id}/{run_id}/

Each step should be saved as:

step_000/
step_001/
step_002/

Each step directory should contain observation, model response, parsed action, and execution result.

## Evaluation Metrics

Required metrics:
- task success rate;
- average steps;
- average time;
- action validity rate;
- grounding error rate;
- correction success rate;
- failure type distribution.

Useful ablations:
- with vs without Set-of-Marks;
- screenshot only vs screenshot + DOM;
- with vs without Progress Checker;
- different model backends.

## Done Criteria

A feature is complete only if:
1. It has a runnable script or test.
2. It writes trace files when relevant.
3. It is documented in README.md.
4. It does not break existing demo scripts.
5. It avoids unsafe browser operations.
